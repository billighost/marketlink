Farmer API (`/api/farmer/*`, role `farmer`)**Approval gating**: a Farmer with status `pending`, `suspended` or `rejected` can sign in and use **read-only profile and order views** but every **create/edit product** action returns 403 `FARMER_NOT_APPROVED` (pending) or `ACCOUNT_SUSPENDED`. Profile edits are allowed while pending.### Profile and stall- `GET /farmer/profile`, `PATCH /farmer/profile`: stall name, contact person, phone, story, specialty, `since`, address, `location { lat, lng }` (the **map pin**, validated ranges), `marketIds` (only existing active markets), `operatingDays[]`, `pickupWindows[ { day, startMin, endMin } ]` (validate: within operating days, start < end, no overlap), `cutoffMinutesBefore` (30..4320), `maxOrdersPerSlot`, `imageUrl`.- When `stallName` or `stallNumber` changes: `updateMany` the denormalised `farmer` snapshot on that Farmer's products. When `marketIds` change: `updateMany` `products.marketIds` and recompute `markets.farmerCount` with `$inc` for added/removed markets (atomic, no full recount). Keep `categorySlugs` in sync when products change.- `GET /farmer/slots?days=14` → upcoming slots with `ordersCount`, `capacity`, `closed`; `PUT /farmer/slots/closures` `{ dates: [...], reason? }` and `DELETE /farmer/slots/closures/:date` manage `slotOverrides` ("manage available pickup slots").### Stock and pricing- `GET /farmer/products?availability=&q=&category=&cursor=` (includes hidden and archived when `includeArchived=true`), returns stock rows (`id, name, category, priceCents, unit, quantityAvailable, lowStockThreshold, availability, weekly, imageUrl, art, tags, updatedAt`).- `POST /farmer/products`: name (2..80), `categoryId`, `priceCents` (1..1,000,000), `unit` (enum), `quantityAvailable` (0..10,000), `lowStockThreshold`, `description` (max 500), `tags`, `art`, `imageUrl?`, `weekly { enabled, defaultQty }`. Computes `availability`, `listed`, `nameLower`, `rnd`, denormalised `farmer` snapshot, `marketIds` from the Farmer, `categorySlug`, keeps `farmers.categorySlugs` in sync.- `PATCH /farmer/products/:id` (ownership in the filter: `{ _id, farmerUserId }`, 404 otherwise): any editable field; recompute `availability` and `listed`; a quantity going **from 0 to above 0** calls `notifyRestock` (batched).- `POST /farmer/products/:id/sold-out` and `/available` (toggles; sold out sets quantity 0 or `availability: 'out'` consistently; "temporarily unavailable" sets `availability: 'hidden'`, `listed: false`).- `PATCH /farmer/products/bulk` `{ ids: [...], action: 'sold-out'|'hide'|'show'|'set-quantity', quantity? }` using one `bulkWrite`.- `DELETE /farmer/products/:id`: hard delete when **no order references it**, otherwise soft delete (`archived: true`, `listed: false`) and return which happened. Removes it from favourites (`deleteMany`).- **Weekly template**: `GET /farmer/weekly-template` (products with `weekly.enabled`), `PUT /farmer/weekly-template` `{ items: [ { productId, enabled, defaultQty } ] }` (`bulkWrite`), `POST /farmer/weekly-template/apply` → sets each enabled product's `quantityAvailable = defaultQty` and recomputes availability with a **single pipeline `updateMany`/`bulkWrite`**, fires `notifyRestock` for items that were out, returns a summary.- **Images**: `POST /farmer/uploads/image` (raw body, `Content-Type` `image/jpeg|png|webp`, **max 1 MB**, no extra packages: use `express.raw`). Validate **magic bytes** (not just the header), generate a random filename, save under `backend/uploads/`, never use client names or paths, return `{ imageUrl: '/uploads/<name>' }`. Serve `/uploads` statically with long cache headers, `X-Content-Type-Options: nosniff`, no directory listing. Rate limit (20/hour). Document that team members must use images they own or that are licensed (project constraint in the brief).### Orders (Farmer)- `GET /farmer/orders?status=&date=&cursor=` (with `meta.counts { placed, accepted, ready, completed, cancelled }` from one grouped, indexed aggregate), `GET /farmer/orders/:id` (ownership via `{ _id, farmerUserId }`; shows Customer first name and last initial, phone only once the order is `accepted`, and the note).- `POST /farmer/orders/:id/accept`, `/decline` (`{ reason }` required, 3..200), `/ready`, `/complete`, `/cancel` (`{ reason }`), all through **`transitionOrder`** (conditional update, timeline, stock restore, notifications to the Customer, email stubs). Wrong state → 409 `INVALID_TRANSITION`.- `GET /farmer/orders/pick-list?date=YYYY-MM-DD` → aggregated **packing list** for a pickup day: per product total quantity across accepted/placed orders plus per-slot order list (single aggregation on `{ farmerId, 'pickup.start' }`).### Reviews (Farmer)- `GET /farmer/reviews?unanswered=true&target=farmer|product&cursor=` (with `meta.summary { ratingAvg, ratingCount, breakdown, unanswered }`).- `POST /farmer/reviews/:id/reply` `{ text (2..500) }` (create or edit own reply), `DELETE /farmer/reviews/:id/reply`; notifies the Customer (`review_reply`). Only reviews about that Farmer or their products.### Overview and insights- `GET /farmer/overview`: `{ pendingOrders (latest 5 placed with items summary), counts, revenueThisWeekCents, lowStock[5], nextPickup: { date, ordersCount, cutoffAt }, approvalStatus }` in one round trip (parallel indexed queries).- `GET /farmer/insights?range=7d|30d|90d`: **total orders, pending orders, completed, cancelled, revenue (completed only, cents), average order value, repeat Customers, best sellers (top 5 by quantity and by revenue), orders per day series (with zeros filled)**. One `$facet` aggregation over the indexed range; cache per Farmer for 30 seconds in memory (comment the trade-off).---## 4.
