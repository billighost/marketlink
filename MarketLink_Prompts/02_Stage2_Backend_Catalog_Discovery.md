Schema additions (apply the "Schema changes procedure")- `products.listed` (bool): **true iff** the Farmer's `listingEnabled` is true, `moderation.removed` is false and `availability !== 'hidden'`. Denormalised so catalog queries filter on **one indexed boolean**. Stage 4 keeps it in sync; the seed sets it. Rebuild the product indexes as **partial indexes with `partialFilterExpression: { listed: true }`** where sensible (Browse, market view, popularity) so they stay small and fast.- `products.nameLower` and `farmers.stallNameLower` (prefix-search fields) with indexes `{ listed: 1, nameLower: 1 }` and `{ listingEnabled: 1, stallNameLower: 1 }`.- `products.rnd` and `farmers.rnd` (random float in `[0,1)` assigned at creation) with indexes `{ listed: 1, rnd: 1 }` and `{ listingEnabled: 1, rnd: 1 }`: a fast, index-based pseudo-random sampler for the feed (no `$sample`, no collection scan).- `farmers.categorySlugs[]` (denormalised from their products; Stage 4 keeps it in sync) with index `{ listingEnabled: 1, categorySlugs: 1, ratingAvg: -1 }`.- `products.ratingSum` and `farmers.ratingSum` (integers; Stage 3 maintains them with `$inc`; `ratingAvg` derived). The feed engine (`src/modules/feed/`)`GET /feed` returns **batches of sections** so the front end can scroll forever. Response: `{ data: { sections: [...] }, meta: { nextCursor, batch } }`.A **section**: `{ id, type, title, subtitle?, seeAll?: { path: '/products', query: {...} }, items: [...] }`, where `type` is one of `featureRow | productRow | farmerRow | categoryStrip | quickPicks`, and `items` use `productCard`, `farmerCard`, or `{ slug, name, art, count }` for category tiles.**Batch 0 (curated, fixed order)**: `Featured today` (`featureRow`, 3 hand-picked-by-rule items: high rating, in stock, tagged seasonal or bestseller, from different Farmers), `Recently bought` (`productRow`, the caller's last purchased products from completed orders, deduplicated, with `lastBoughtAt`; omit the section when empty), `Top-selling Farmers` (`farmerRow`), `Order soon` (`productRow`, items whose Farmer's cut-off is within the next 24 hours, each with `cutoffAt`), `New this week` (`productRow`, created in the last 7 days), then a personalised `From <Farmer>` row if the caller has a favourite Farmer (Stage 3 adds favourites; implement now by reading `favorites` and returning nothing when there are none).**Batches 1..n (endless "more for you")**: the cursor is an opaque base64 string carrying `{ batch, seed }`. Each batch returns 3 sections chosen from **at least 12 templates** (e.g. "Because you like tomatoes" using the caller's recent categories, "Under $5", "Still warm from the oven", "Sunday morning picks", "Farmers you might love", "Pantry staples", "Fresh eggs and dairy", "Sweet things", "Popular at <market>", "Back by popular demand", "From small farms", "Quick pickup picks" as `quickPicks`), mixing row types. Selection is **deterministic from `(userId, batch)`** so refresh returns the same sections, but **items do not repeat within a window of 6 batches**: walk the `rnd` index from an offset that advances per batch (`{ rnd: { $gte: x } }` sorted by `rnd`, wrap around with a second query when the end is reached) and exclude ids already used earlier in the same batch. The feed **never ends**: after the last template the cycle restarts with fresh offsets.**Performance**: all queries of a batch run in parallel (`Promise.all`), each is index-backed and projected, the whole `GET /feed` responds in under 80 ms on the seeded DB and under 120 ms on the large dataset from Stage 5.Also expose `GET /feed/meta` (auth): `{ homeMarket, nextOpening, nextCutoffAt, greetingName }` for the header sub-line ("Elm Street Market opens Saturday at 8am. Order by Friday, 6pm."), using the caller's `homeMarketId` (fall back to the nearest or first market).---## 6.
